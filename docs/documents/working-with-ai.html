Working with AI

Note

Draft worksheet. This is a first pass for instructor review — content, examples, and exercises are still open to editing before this goes live for students.

AI tools (ChatGPT, Claude, Copilot, and similar) are increasingly part of how people write code and explore data. This worksheet is about using them well in a data visualization workflow — knowing where they genuinely help, and where they can quietly lead you astray.

We’ll use the same lens as the rest of this module: exploratory versus explanatory. AI is a different kind of tool in each phase.

Recap: exploratory vs. explanatory

  • Exploratory: examine the structure of your data.
  • Explanatory: tell a story with your data.

Recall the discussion from lecture: “What is more important? An eye or an algorithm?” Anscombe’s quartet and the datasaurus_dozen package make the point that identical summary statistics can hide wildly different underlying structure — you only find that out by actually looking. Keep that question in mind throughout this worksheet: an AI tool reasoning over a description of your data has exactly the algorithm’s blindness, not the eye’s.

AI during exploration

Where it helps

  • Writing boilerplate/starter code (ggplot() scaffolding, dplyr pipelines, faceting syntax) so you spend less time on syntax and more on interpretation.
  • Explaining error messages, or translating code between base R and ggplot2/tidyverse style.
  • Brainstorming which variables or relationships might be worth investigating, as a starting point for your own exploratory plots.

Where it doesn’t

  • AI cannot look at your data. Unless you paste in an actual plot or the real values, it is reasoning from whatever you describe to it in words or summary statistics — and summary statistics can hide structure (that’s the whole point of Anscombe/datasaurus). An AI tool can describe a relationship confidently without ever having “seen” its shape, and it can hallucinate patterns that aren’t there.
  • It can suggest a pattern that turns out to be noise, or an artifact of how the data happened to be filtered. Treat any AI-suggested “interesting pattern” as a hypothesis to check by plotting — not a finding.
A hard rule for this course

The Prowise/Oefenweb data you work with is governed by GDPR, and you’ve already agreed to specific terms to access it. That means: never paste real Oefenweb/Prowise data — even small excerpts — into an external AI tool. This is the same principle behind “never push data to GitHub.” If you want to demonstrate an AI workflow, use synthetic or public data (e.g. datasaurus_dozen) instead.

AI during explanation

Where it helps

  • Critiquing communication: “Is this title clear?”, “Does this caption actually match what the plot shows?”, “Is this color scheme colorblind-safe?” — use it as a reviewer of your plot, not the author of your story.
  • Polishing code: consistent styling, catching things a linter would flag, tidying up theme()/patchwork boilerplate.
  • Generating alternative phrasings for a title or annotation once you already know what conclusion you want to communicate.

Where it doesn’t

  • AI cannot tell you whether your story is true. It will happily generate a confident, well-written narrative around whatever effect you show it — real or spurious. Deciding how robust a finding is (part of your Assignment 2 rubric) is a judgment call you have to make, informed by your own exploration.
  • It won’t push you to try the “one dataset, many visualizations” exercise from lecture — the first plot (AI-suggested or not) is rarely the best one. That iteration is still on you.

Exercise: describe it, then look at it

A quick way to feel the “eye vs. algorithm” gap yourself:

  1. Pick one dataset from the datasaurus_dozen package, but don’t plot it yet.
  2. Describe it to an AI tool using only summary statistics (mean, sd, correlation of x and y) and ask it to describe the relationship between the variables.
  3. Now actually plot it:
library(datasauRus)
library(ggplot2)

datasaurus_dozen |>
  dplyr::filter(dataset == "dino") |>
  ggplot(aes(x = x, y = y)) +
  geom_point() +
  theme_minimal()
  1. Compare the AI’s description to what you actually see. Where did it match? Where was it flat-out wrong, or vague in a way that hid the real structure?

(Instructor note: consider swapping in a second datasaurus_dozen shape, or a small anonymized/simulated excerpt of Prowise-style data, so students can’t just search for the “reveal” online.)

Course policy on AI use

AI-assisted code is held to the same bar as any other code in this course:

  • It must run, and be lintr-proof, like any other submission.
  • You need to be able to explain your own code — “comment your code clearly, we want to understand your thought process” applies whether you or an AI tool wrote the first draft.
  • Never paste real Oefenweb/Prowise data into an external AI tool (see above).

Takeaway

🧠 AI accelerates, but does not replace, looking at your data.
